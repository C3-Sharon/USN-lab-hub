### B1：V10 迁移与数据库约束

- 状态：VERIFIED
- 预计工时：3-5 小时
- 目标：V9 数据无损升级到 V10，并由数据库约束模板版本唯一性和每模板最多一个 DRAFT。
- 业务理由：版本记录是后续实验复现的长期事实，迁移错误会破坏第 5 周学习数据或允许歧义草稿。
- 输入与依赖：W42 §5、模板契约 §3/§11、V9 学习路线迁移、现有 Flyway 测试模式。
- 修改边界：只新增 V10 SQL、迁移测试和本台账；不新增 Controller、Service、Mapper 或 API。
- 预期产物：两张模板表；`lab_learning_unit.template_version_id`；版本号唯一键、单 DRAFT 约束及查询索引；H2 和可选 MySQL 迁移测试。
- 契约影响：数据库按冻结契约新增；API、MQTT、权限、缓存、异步和 UI 字段无实现变化。
- 风险与失败表现：Flyway 无法升级；旧数据被修改；重复版本或第二个 DRAFT 可插入；MySQL/H2 DDL 不兼容。
- 定向验证：运行 `ExperimentTemplateMigrationTest`，验证 V9→V10、旧数据保持、表/列/索引存在、唯一约束和 DRAFT 约束。
- 人工验证：使用唯一命名临时数据库在本机 MySQL 8 执行完整 Flyway V1→V10 和约束验证，完成后删除临时库。
- 完成条件：定向测试通过；迁移无数据更新；差异只含 B1 文件；台账记录实际证据。
- 下一块入口：B1 提交推送后暂停，等待用户确认进入 B2。
- 实际结果：新增 V10 两张表和学习单元增量列；H2 与 MySQL 8 均迁移到 V10；验证旧项目、设备、学习单元数据保持，重复版本号、第二个 DRAFT 和非法状态槽均被数据库拒绝；真实 MySQL 临时库已清理。
