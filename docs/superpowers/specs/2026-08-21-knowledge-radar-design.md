# USN Lab Hub Knowledge Radar 设计规格

> 状态：已审阅确认，待随总体规划 PR 合入 `dev`
> 日期：2026-08-21
> 交付约束：Knowledge Radar 属于六个月完整成品，不作为周期外增强项

## 1. 目标

Knowledge Radar（知识雷达）帮助实验室持续发现与当前项目、BOM、元器件、硬件版本、设备和学习路线相关的新资料。它将外部资料先放入候选箱，由有权限的人审核，再进入下载、解析、索引和发布流程。

知识雷达不是自动爬取一切网页的通用搜索引擎，也不是绕过授权的内容采集器。Agent 可以发现知识缺口、推荐关键词和来源，但不能自行启用来源、下载资料、批准候选或扩大资料可见范围。

## 2. 核心决策

1. 知识雷达在第 18-21 周完成，并进入第 26 周最终验收。
2. 来源采用管理员配置的域名/入口与关键词白名单；Agent 只能提出新增建议。
3. 普通更新进入站内候选箱和每周摘要；Errata、停产、安全风险和关键规格变化即时提醒。
4. 项目负责人可以批准自己项目的私有知识；实验室公共知识由老师/实验室负责人或管理员批准。
5. 全局白名单域名只有管理员可以启用。
6. 外部候选未经批准不能下载到长期知识库，不能参与正式 RAG，不能修改 Knowledge Atlas。
7. 产品能力不拆成周期外版本；知识资源本身保留历史版本，保证项目与硬件设计可追溯。
8. Java 自研来源注册、Connector SPI、调度、游标、候选、审批、差异、任务和通知编排；不自研通用浏览器、OCR、搜索引擎或网页解析底层算法。
9. 微信公众号只支持成员提交公开文章链接，不承诺自动订阅公众号、批量抓取或绕过登录。

## 3. 来源范围

六个月成品必须支持：

| 来源类型 | 典型内容 | 发现方式 | 下载条件 |
|---|---|---|---|
| `RSS_ATOM` | 厂商新闻、比赛通知、技术博客 | 定时读取订阅 | 候选批准后下载正文或附件 |
| `OFFICIAL_WEB_PAGE` | TI/ST/Espressif 产品页、数据手册、Errata | URL、关键词、ETag/更新时间/哈希 | 白名单域名且候选批准 |
| `GITHUB_RELEASE` | 固件、工具、依赖和实验室项目发布 | GitHub API 增量检查 | 候选批准；附件类型受限 |
| `MANUAL_URL` | 成员发现的公开网页 | 人工提交 | 项目负责人或更高权限批准 |
| `UPLOADED_FILE` | PDF、DOCX、PPTX、Markdown、内部记录 | 人工上传 | 上传者有目标空间写权限并通过审核 |
| `VENDOR_ALERT` | myTI 等产品提醒 | 管理员粘贴提醒链接或关联产品提醒 | 候选批准；不建设邮件服务器 |
| `WECHAT_ARTICLE` | 公众号技术文章、经验和比赛信息 | 成员提交公开文章链接 | 项目负责人或更高权限批准 |

微信公众号文章抓取失败时，允许提交 PDF、网页快照或正文文件作为替代。系统保存公众号名称、标题、作者、发布时间、原文 URL、发现和访问时间。资料只用于授权范围内的内部检索与引用，不自动公开转载全文。

来源优先级为：已审核实验室知识 > 官方厂商资料 > 项目正式文档 > 已审核外部技术内容 > 未审核实验记录 > 外部候选 > Agent 推断。公众号文章不能覆盖官方数据手册中的电气参数事实。

## 4. 来源配置与 Agent 建议

一个订阅配置包含：

- 来源类型、显示名称、域名和入口 URL。
- 关键词、器件型号、厂商、产品系列和排除词。
- 关联实验室、项目、BOM、元器件、硬件版本或学习路线。
- 检查周期、时区、内容类型和最大下载大小。
- 负责人、可见范围、即时提醒条件和启用状态。
- 最近成功时间、最近失败时间、连续失败次数和同步游标。

Agent 建议流程：

```text
识别知识缺口
-> 生成 SOURCE_PROPOSAL
-> 说明关联对象、关键词、来源 URL、推荐理由和预计范围
-> 管理员检查域名和抓取范围
-> APPROVED / REJECTED
-> 批准后才创建有效订阅
```

Agent 不能批准自己的提案，也不能通过修改 URL、重定向或网页内容突破域名白名单。

## 5. Connector SPI

知识雷达采用内置 Java Connector SPI：

```java
public interface KnowledgeSourceConnector {
    SourceType supports();
    DiscoveryResult discover(SourceConfig source, SyncCursor cursor);
    DownloadedResource download(ApprovedCandidate candidate);
}
```

`discover` 只返回候选元数据、远端标识、更新时间、内容摘要和下一游标，不直接发布知识。`download` 只能接受已经批准且仍在有效期内的候选，并由受控下载网关执行。

连接器输出统一字段：`externalId`、`canonicalUrl`、`title`、`author`、`publishedAt`、`updatedAt`、`contentType`、`contentLength`、`etag`、`lastModified`、`sourceChecksum`、`summary` 和 `nextCursor`。

内置连接器与通用流程解耦。增加新厂商时优先复用 `OFFICIAL_WEB_PAGE`，只有身份验证、分页或差异语义显著不同才新增专用 Connector。

## 6. 同步和变化检测

每个来源支持手动检查、增量检查和受控全量复核：

- 首次启用执行全量发现，但只生成受数量上限约束的候选。
- 日常使用远端 ID、更新时间、ETag、Last-Modified、内容哈希和游标增量发现。
- 来源规则或关键词变化后执行全量复核。
- 外部来源不提供可靠时间戳时，可以抓取允许的轻量内容计算规范化哈希。
- 同一 `sourceId + externalId + sourceChecksum` 只能生成一个候选。
- 重定向后的最终域名仍必须位于白名单。

双实例部署下，调度器通过数据库任务抢占或租约保证同一来源同一计划窗口只有一个执行者。数据库唯一约束承担最终幂等，不依赖分布式锁保证事实正确。

调度使用有界线程池，按来源隔离并发，设置连接/读取超时、单次最大候选数、单文件大小和域名速率上限。连续失败采用有上限的退避；权限失败、域名越界和不支持类型不自动重试。

## 7. 候选、审批与任务状态

候选状态：

```text
DISCOVERED -> REVIEWING -> APPROVED -> DOWNLOADING
           -> REJECTED     -> INGESTING -> READY_TO_PUBLISH -> ACTIVE
           -> IGNORED

失败：DOWNLOAD_FAILED / INGEST_FAILED
```

候选记录包含来源、目标空间、关联对象、推荐理由、变化类型、重要级别、旧/新版本摘要、命中关键词、审批人和审计时间。

候选箱采用类似邮件收件箱的工作台，提供未读、待审核、已批准、已拒绝和失败视图。可信来源的普通低风险资料允许批量批准；Errata、停产、安全风险和关键规格变化始终逐条确认。

批量批准仍逐条创建审计记录和幂等下载任务。审批时重新校验权限、候选状态、来源状态和目标空间，防止候选生成后权限变化导致越权发布。

## 8. 权限

| 操作 | 普通成员 | 项目负责人 | 老师/实验室负责人 | 系统管理员 |
|---|---:|---:|---:|---:|
| 提交链接、文件或来源建议 | 是 | 是 | 是 | 是 |
| 批准项目私有知识 | 否 | 自己的项目 | 是 | 是 |
| 批准实验室公共知识 | 否 | 否 | 是 | 是 |
| 启用全局白名单域名 | 否 | 否 | 建议 | 是 |
| 撤回项目知识 | 否 | 自己的项目 | 是 | 是 |
| 撤回公共知识 | 否 | 否 | 是 | 是 |

项目负责人批准的资料只进入项目知识空间。提升为实验室公共知识时重新审核版权、可信度、内容质量和 ACL，不直接继承项目批准结果。

## 9. 知识资源版本

```text
旧 ResourceVersion ACTIVE
-> 雷达发现变化候选
-> 审批并完成新版本摄取
-> 新 ResourceVersion 原子切换 ACTIVE
-> 旧版本标记 SUPERSEDED
```

普通 RAG 默认只检索最新审核的 ACTIVE 版本。项目、BOM、硬件版本和实验记录可以固定绑定历史 ResourceVersion；历史上下文查询优先使用绑定版本。SUPERSEDED 版本不参与普通检索，但保留引用、文件、哈希和审计。

管理员撤回错误资料时先禁止检索，再异步清理派生索引；MySQL 中的资源事实和审计记录保留。新版本摄取失败时旧 ACTIVE 版本继续服务。

## 10. 与 RAG Kernel 和 Agent 的边界

```text
Knowledge Radar    找到值得审核的外部资料
Knowledge Governance 决定谁能批准、发布、撤回和查看
RAG Ingestion      解析、规范化、切块、Embedding 和索引
RAG Kernel         检索、融合、上下文组装、引用和评测
Agent              识别缺口、提出建议、使用授权知识和工具
```

外部候选在 ACTIVE 前不能进入正式检索。原始网页、公众号文章和资料中的 Prompt、指令、链接和工具描述始终作为不可信数据，不能提供工具授权。

RAG 回答必须显示来源类型、标题、版本、发布日期或访问时间和原始链接。官方来源与外部经验冲突时并列提示，不让模型静默融合成一个伪事实。

第 23 周 Agent 可以查询知识覆盖、来源订阅和候选状态，并创建 `SOURCE_PROPOSAL`，但没有批准、下载、发布或白名单工具。

## 11. 通知

- 普通新增和更新：站内候选箱 + 每周摘要。
- Errata、停产、安全风险、关键规格变化：即时站内通知。
- 来源连续失败：通知来源负责人和管理员，不通知全部成员。
- 下载或摄取失败：进入失败视图，提供可解释阶段、错误类型和重试入口。
- 重复候选、无实质变化和已忽略内容：不反复通知。

通知只说明发现和风险，不把 Agent 摘要当作经过审核的最终事实。

## 12. 安全与合规

- 只允许 `https` 和明确批准的 `http` 内网来源，禁止 `file`、`ftp` 和任意自定义协议。
- DNS 解析和每次重定向后检查公网/内网范围，阻止访问回环、链路本地、云元数据和未授权内网地址。
- 限制重定向次数、响应大小、MIME、压缩展开大小、连接/读取时间和下载总时长。
- 不执行网页脚本，不使用页面内容生成请求头、凭据或下一个任意下载 URL。
- 凭据按来源加密保存并脱敏，不进入日志、Trace 或 Agent 上下文。
- 遵守来源服务条款、robots 和访问频率；受限或需要登录的内容改为人工上传。
- 微信公众号内容不自动公开转载全文，公开成果页只显示经授权的摘要和原文链接。

## 13. 前端工作台

知识雷达位于“知识与智能 -> 知识雷达”，包含：

1. 候选箱：五个状态视图、来源/项目/类型/重要性筛选和批量低风险审批。
2. 候选详情：元数据、关联对象、推荐理由、来源可信度、版本差异、审批和审计。
3. 来源管理：白名单、关键词、关联范围、周期、健康状态、最近同步和手动检查。
4. 同步任务：阶段、游标、数量、耗时、失败原因和有权限的重试。
5. Agent 建议：独立显示为来源提案，不与已经发现的资料候选混淆。

重要状态不只依赖颜色。Errata、停产和安全风险使用明确文字和图标。微信公众号候选显示公众号、作者、发布日期和“外部经验来源”标识。

## 14. Java 工程能力

| 能力 | Knowledge Radar 场景 |
|---|---|
| SPI/策略 | RSS、网页、GitHub、微信提交等 Connector |
| 调度与多线程 | 动态计划、有界线程池、来源隔离和背压 |
| 幂等与一致性 | 候选唯一键、重复审批、下载和摄取任务 |
| 双实例协调 | 数据库抢占/租约与超时恢复 |
| Outbox | 批准后下载、摄取、通知的可靠触发 |
| 增量同步 | Cursor、ETag、Last-Modified 和内容哈希 |
| 缓存 | 来源配置和低风险公共元数据；事实仍在 MySQL |
| 安全 | SSRF、重定向、白名单、MIME 和下载限制 |
| 可观测 | 来源成功率、候选量、延迟、失败阶段和队列积压 |
| 容灾 | 任务续跑、旧 ACTIVE 继续服务、索引可重建 |

## 16. 完整验收

1. 管理员配置 TI 官方来源、器件型号和检查周期。
2. 雷达发现新增数据手册或 Errata，生成候选并显示变化。
3. 项目负责人批准项目私有资料，普通成员不能批准。
4. 下载、校验、摄取和发布完成，RAG 引用新 ACTIVE 版本。
5. 历史硬件版本仍能引用绑定的旧资料版本。
6. 成员提交微信公众号公开文章，审批后进入项目知识库。
7. Agent 识别 BOM 资料缺口并提出来源建议，但不能自行启用或下载。
8. 模拟来源超时、重定向越界、重复内容、非法文件和摄取失败，系统正确拒绝或恢复。
9. 两个应用实例同时调度时，同一来源窗口和同一候选不会重复执行或入库。
10. 普通更新进入周摘要；Errata 或停产变化产生即时提醒且必须逐条审批。

## 17. 明确不做

- 通用互联网搜索引擎或任意网页爬虫平台。
- 自动监控微信公众号、绕过登录、验证码、访问限制或批量抓取历史文章。
- 自研浏览器渲染、OCR、向量数据库、网页正文提取底层算法。
- Agent 自动批准来源、资料或公开范围。
- 外部资料自动替换 BOM、元器件规格或硬件控制参数。
- 通过邮件协议建设完整厂商提醒收件服务器。
