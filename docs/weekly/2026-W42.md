## 1. 本周目标

建立实验模板与版本管理的完整契约：

```
老师/项目负责人
→ 创建模板（系统/项目）
→ 编辑 DRAFT 版本（可视化字段配置）
→ 预览模板填写效果
→ 发布不可变的 PUBLISHED 版本
→ 继续编辑下一个 DRAFT 版本
→ 学习单元关联到具体 PUBLISHED 版本
→ 旧版本长期可读，实验记录（第7周）固定引用版本
```

验收核心：**发布新模板版本后，旧版本仍可读取和解释，未来实验记录不会因模板更新而改变结构。**

## 2. 明确不做

- 实验记录和实验内容版本（第 7 周）
- 导师反馈（第 7 周）
- 采集计划、采集批次和实验快照（第 7 周）
- MQTT、串口、蓝牙或文件导入（第 7、16 周）
- 项目草案转换（阶段门缺口，第 7 周决定）
- RAG、Agent、联网推荐
- 通用低代码平台
- 任意脚本执行
- 完整 JSON Schema 引擎（只支持受控子集：string/number/integer/boolean + enum + 基础约束）
- 嵌套对象、数组、$ref、条件 Schema
- 后端和前端业务代码

## 3. 现状与矛盾

1. **第 5 周学习单元只有 `templateId/templateName` 预留字段**，未区分模板主记录和版本。本周新增 `templateVersionId/templateVersion`，保持向后兼容（additive）。
2. **模板归属需要区分系统和项目**——系统模板全局可用，项目模板属于特定项目。两者的可见范围和权限不同。
3. **JSON Schema 不能支持全集**——必须冻结本阶段允许的子集，避免后端实现范围膨胀。
4. **版本不可变性是核心约束**——已发布版本的 Schema 绝对不能修改，否则旧实验记录的结构会变化。
5. **Phase 2 阶段门要求"一条实验记录可以复现并转项目草案"**，但第 7 周路线没有详细冻结项目草案转换。本周记录为缺口。

## 4. 用户场景

### 场景 1：老师创建系统模板并发布

TEACHER 进入学习实验台 → 实验模板管理 → 创建系统模板 → 添加电压、电流等字段 → 预览 → 发布 v1.0.0 → 自动创建 v0.2.0 DRAFT。

### 场景 2：项目负责人复制系统模板为项目模板

项目 OWNER 浏览系统模板 → 选择"电压测量实验" → 复制到自己的项目 → 调整字段 → 发布项目模板版本。

### 场景 3：老师编辑草稿并发布新版本

TEACHER 编辑 DRAFT 版本 → 新增温度字段 → 预览 → 发布 v1.1.0 → 学习单元仍引用 v1.0.0（不自动升级）。

### 场景 4：学习单元关联模板版本

TEACHER 编辑学习单元 → 选择关联的模板和版本 → 单元显示模板名称和版本号 → 成员学习时可查看模板结构。

### 场景 5：废弃旧版本

TEACHER 发现 v1.0.0 有设计问题 → 废弃 v1.0.0 → 已关联的单元仍可用但显示"已废弃"提示 → 新关联只能选择 v1.1.0。

### 场景 6：成员预览实验模板结构

MEMBER 在学习单元中点击"查看实验模板" → 看到字段列表和说明 → 知道实验需要记录什么数据。

### 场景 7：并发发布版本冲突

两个 TEACHER 同时编辑同一个模板的 DRAFT → 同时点击发布 → 一个成功，另一个收到版本号冲突 → 刷新后使用新的 DRAFT 版本重新编辑。

## 5. 已冻结内容（REVIEW，待确认）

### 5.1 模板归属两档

- **系统模板（SYSTEM）**：全局可见，由 SYSTEM_ADMIN/TEACHER 创建和管理
- **项目模板（PROJECT）**：属于特定项目，由项目 OWNER/MAINTAINER 创建和管理
- 支持从系统模板复制为项目模板，不支持反向复制

### 5.2 模板与版本分表

- 模板主表（lab_experiment_template）：元数据
- 版本表（lab_experiment_template_version）：Schema + 版本状态
- 版本号：语义化版本（1.0.0、1.1.0），DRAFT 为 0.X.0
- 每个模板同时最多一个 DRAFT 版本
- 已发布版本绝对不可修改
- 发布后自动创建下一个 DRAFT
- 并发发布由数据库唯一约束防止重复版本号
- 禁止物理删除，采用逻辑删除 + 废弃机制
- 旧版本永久可读

### 5.3 JSON Schema 子集

支持的类型：string、number、integer、boolean
支持的约束：enum、required、default、minimum/maximum（数值）、minLength/maxLength（字符串）
扩展元数据：title、description、unit、displayOrder、widget
明确不支持：嵌套对象、数组、$ref、oneOf/anyOf/allOf、条件 Schema、pattern、format、脚本执行

### 5.4 学习单元关联

- 单元同时有 templateId（主记录）、templateVersionId（具体版本）
- 只能关联 PUBLISHED 版本
- 模板发布新版本后，单元不自动升级
- 已废弃版本的关联保留，但显示提示
- 新增字段为 additive，不破坏第 5 周接口兼容性

### 5.5 第 7 周预留规则

- 实验记录必须固定引用 templateVersionId
- 模板更新不得重解释旧记录
- 不保存 Schema 快照（因为已发布版本本身不可变）
- 模板版本禁止物理删除
- 采集批次和实验快照通过实验记录间接关联模板

### 5.6 权限矩阵

- SYSTEM_ADMIN / TEACHER：管理系统模板 + 项目模板
- 项目 OWNER / MAINTAINER：管理本项目模板
- MEMBER / STOCK_KEEPER：查看已发布模板（系统 + 所在项目）
- GUEST：不可访问

### 5.7 API 接口（12 个）

模板：创建、列表、详情、编辑、复制
版本：列表、详情、编辑 DRAFT、发布、废弃、已发布版本列表
Schema 校验：数据校验（预览用）

### 5.8 前端交互

- 模板列表（系统/项目 tab 切换、筛选、搜索）
- 模板编辑器（左侧字段列表 + 右侧属性面板、拖拽排序）
- 模板预览（实时渲染填写效果、测试数据校验）
- 版本历史（时间线、状态标签）
- 发布确认对话框
- JSON Schema 原始模式（只读）
- 三视口适配

### 前置条件
- 后端服务运行在 localhost:8080
- 前端运行在 localhost:5173
- MySQL 8 运行，Flyway 已迁移到 V10
- 已有 SYSTEM_ADMIN 账号 admin/admin123
- 已有 TEACHER 账号 teacher01/123456
- 已有 MEMBER 账号 student01/123456
- 已有项目（id=1，owner=student01 不对，应该有 OWNER 角色的项目成员）

### 步骤 1：老师创建系统模板
```bash
# teacher01 创建系统模板
curl -s -X POST http://localhost:8080/api/experiment/templates \
  -H "Authorization: Bearer $TEACHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"电压测量实验","scope":"SYSTEM","category":"电路测试"}'
# 断言：返回 200，scope=SYSTEM，publishedVersionCount=0
```

### 步骤 2：编辑 DRAFT 版本 Schema
```bash
# 编辑 DRAFT 版本（假设 versionId=1）
curl -s -X PUT http://localhost:8080/api/experiment/templates/1/versions/1 \
  -H "Authorization: Bearer $TEACHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "schemaJson": {
      "schemaVersion":"1.0","type":"object",
      "properties":{
        "voltage":{"type":"number","title":"电压","unit":"V","minimum":0,"maximum":24,"displayOrder":1,"widget":"input-number"}
      },
      "required":["voltage"]
    },
    "changelog":"初始版本"
  }'
# 断言：返回 200，status=DRAFT，fieldCount=1
```

### 步骤 3：Schema 校验失败（包含不支持的类型）
```bash
# 尝试保存包含 array 类型的 Schema
curl -s -X PUT http://localhost:8080/api/experiment/templates/1/versions/1 \
  -H "Authorization: Bearer $TEACHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"schemaJson":{"properties":{"data":{"type":"array"}}}}'
# 断言：返回 400 SCHEMA_INVALID，errors 包含 path 和 message
```

### 步骤 4：发布版本
```bash
# 发布 DRAFT 版本
curl -s -X PUT http://localhost:8080/api/experiment/templates/1/versions/1/publish \
  -H "Authorization: Bearer $TEACHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"changelog":"首次发布"}'
# 断言：返回 200，publishedVersion.version=1.0.0，status=PUBLISHED
# 断言：newDraftVersion.version=0.2.0，status=DRAFT
```

### 步骤 5：已发布版本不可编辑
```bash
# 尝试编辑 PUBLISHED 版本
curl -s -X PUT http://localhost:8080/api/experiment/templates/1/versions/2 \
  -H "Authorization: Bearer $TEACHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"schemaJson":{"properties":{}}}'
# 断言：返回 409 TEMPLATE_VERSION_NOT_EDITABLE
```

### 步骤 6：成员查看已发布模板
```bash
# student01 查看模板列表
curl -s http://localhost:8080/api/experiment/templates?status=PUBLISHED \
  -H "Authorization: Bearer $STUDENT_TOKEN"
# 断言：返回 200，list 包含"电压测量实验"
# 断言：看不到 DRAFT 版本相关信息
```

### 步骤 7：数据校验（预览）
```bash
# 校验一份数据
curl -s -X POST http://localhost:8080/api/experiment/templates/1/versions/2/validate-data \
  -H "Authorization: Bearer $TEACHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"voltage": 5.5}'
# 断言：返回 200，valid=true
```

### 步骤 8：复制系统模板为项目模板
```bash
# admin 复制到项目
curl -s -X POST http://localhost:8080/api/experiment/templates/1/copy \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"targetProjectId":1,"title":"项目电压校准"}'
# 断言：返回 200，scope=PROJECT，projectId=1
```

### 步骤 9：废弃版本
```bash
# 废弃 v1.0.0
curl -s -X PUT http://localhost:8080/api/experiment/templates/1/versions/2/deprecate \
  -H "Authorization: Bearer $TEACHER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"reason":"有新版本替代"}'
# 断言：返回 200，status=DEPRECATED
```

### 步骤 10：GUEST 不可访问
```bash
# 无 token 访问
curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/experiment/templates
# 断言：返回 401
```

## 11. 第 7 周待确认输入

第 7 周产品契约必须决定以下二选一：

1. **实现轻量的实验记录转项目草案**：
   - 实验记录完成后，老师或项目负责人可以"转为项目草案"

   - 项目草案可以进一步转为正式项目

2. **给出明确恢复周和不影响 v0.3 的依据**：
   - 如果第 7 周不实现项目草案转换，必须明确说明
   - 指定恢复周（如第 12 周或第 24 周）和被替换的次要工作
   - 说明 v0.3 阶段门如何调整或降级

**不得静默删除该阶段门。**
