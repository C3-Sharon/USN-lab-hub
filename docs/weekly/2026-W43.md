## 3. 主流程

```text
选择学习单元/项目和 PUBLISHED 模板版本
→ 创建记录与 revision 1
→ 填写结构化字段和实验上下文
→ 创建 FILE/MANUAL 采集计划与批次
→ CSV 预览映射并确认，或逐条录入人工观测
→ 完成批次并生成 FULL_BATCH 快照
→ 绑定当前可编辑修订并提交
→ 导师评论 / 要求修改 / 批准
→ 发布不可变修订
→ 用户确认字段后创建 PREPARING 项目
```

## 4. 角色与前置数据

- 采集管理者：SYSTEM_ADMIN、项目 OWNER/MAINTAINER；TEACHER 只有在同时担任项目 OWNER/MAINTAINER 时才可管理该项目采集。
- 执行者：计划负责人或被指定的项目成员。
- 预置数据：至少一个可见的 PUBLISHED 模板版本；项目采集还需已有项目和成员关系。
- GUEST 不进入本周所有页面和 API。

## 5. 已确认的冻结结论

详细字段和理由见正式契约 §2。已确认：

1. 记录聚合状态与内容修订状态分离；发布后编辑创建新修订，旧发布版持续有效。
2. 导师要求修改时写不可变反馈并自动复制下一份 EDITABLE 修订，导师不直接改成员内容。
3. 只有 COMPLETED 批次可生成快照；每个修订本周最多绑定 1 个 FULL_BATCH 快照，提交时冻结。
4. CSV 原件保存到可替换的本地不可变存储适配器；仅 UTF-8 CSV，20 MiB、100,000 行、100 列上限。
5. 同批次相同文件哈希幂等复用；映射变化与人工修改均追加修订，不覆盖历史。
6. 只允许 PUBLISHED 实验一次性创建现有 `PREPARING` 项目，保存来源记录/发布修订关系，不新增项目 DRAFT 状态。

补充冻结边界：实验内容只能由记录作者编辑、提交和重新提交；导师、项目管理者和系统管理员通过反馈/评审推进流程，不代改内容。只有 READY 计划可创建批次。FILE 使用已确认导入修订作为快照来源；MANUAL 完成时冻结人工记录有效修订集合，快照 `sourceRevisionId=null`。

确认结果：D1-D6 全部采用推荐方案，契约已改为 FROZEN。后端仍须按后端工作块门禁，在执行 Flyway、权限和事务/并发实现前提交具体设计确认。

## 6. 异常与边界流程

### 6.1 模板与内容

- 模板版本为 DRAFT/DEPRECATED 或不可见：创建记录返回 404/409，不回退到 latest。
- `contentJson` 不符合固定版本：保存可返回字段错误；提交必须阻止并返回 `EXPERIMENT_CONTENT_INVALID`。
- 发布后点击编辑：进入“创建新修订”，不得打开旧修订写入口。

### 6.2 反馈与并发

- 普通成员尝试批准自己记录：403 `FEEDBACK_OPERATION_DENIED`。
- 两个导师同时评审：状态+version 条件更新仅允许一个状态动作成功，另一请求 409 `VERSION_CONFLICT`；COMMENT 可并列追加。
- 导师在旧 revision 上要求修改：409 `EXPERIMENT_INVALID_TRANSITION`，必须刷新到当前送审修订。

### 6.3 文件与人工数据

- 非 CSV、超限、非 UTF-8、路径/内容异常：拒绝导入但保留安全审计，不执行公式或脚本。
- CSV 没有时间列或单位不匹配：允许预览，禁止确认导入，返回映射错误。
- 同文件重复上传：返回已有导入任务；不同映射产生新修订，不重复保存原件。
- 新映射确认成功后，上一份已确认映射修订变为 SUPERSEDED；旧结果只供审计，不进入最终批次集合。
- 完成批次后修改人工记录、映射或再次确认：409 `BATCH_IMMUTABLE`。

### 6.4 快照与项目转换

- 未完成批次不能生成快照；快照与实验项目范围不一致时返回 404/403。
- 已提交修订不能替换快照；要求修改产生的新修订可重新选择。
- 未发布实验不能转项目；同一记录重复转换返回原幂等结果或 409 `PROJECT_ALREADY_CONVERTED`。

## 7. 页面范围

### 实验记录

- 记录列表：我的/项目范围、状态、模板、作者筛选和分页。
- 创建/编辑：固定模板版本提示、结构化表单、实验上下文、草稿版本与保存冲突。
- 详情：当前发布版、当前工作修订、修订时间线、导师反馈、采集快照、项目来源/去向。
- 评审：COMMENT / CHANGE_REQUEST / APPROVAL 三种明确动作，确认对话框展示目标 revision。

### 数据采集

- 项目“数据采集”入口：计划列表、来源、负责人、状态、最近批次。
- 批次详情：来源、处理状态、原件/人工观测、记录摘要、错误样本、完成和生成快照。
- CSV 导入：上传、前 50 行预览、列/单位/时间映射、确认、结果摘要。
- 人工观测：方法、仪器、单位、观测时间、值、备注和修改历史。

### 项目转换

- 发布记录显示“转为项目草案”。
- 确认表单复用现有项目 code/name/summary/category 规则。
- 成功后跳转现有项目详情，状态为 PREPARING，并显示来源实验链接。

所有页面覆盖 loading / empty / error / permission / success / conflict / immutable；固定检查 1440×900、1280×800、390×844。

## 11. 产品验收脚本（冻结后执行）

1. 成员创建项目/学习实验，确认固定 `templateVersionId` 和 revision 1。
2. 保存合规内容；用过期 version 保存，确认 409 且不覆盖。
3. 创建 FILE 计划/批次，上传 CSV；检查原件 SHA-256、50 行预览和未确认不写正式记录。
4. 保存列/单位/时间映射并确认；同 key 重放不重复计数，相同文件重传返回原任务；确认第二份映射修订后旧修订为 SUPERSEDED 且不进入最终集合。
5. 创建 MANUAL 计划/批次，录入方法、仪器、单位、观测时间；更正生成修订且旧值可查。
6. 完成两个批次；确认完成后文件映射、人工记录和计数均不可改。
7. 从完成批次生成快照并绑定实验；未完成批次生成快照必须 409。
8. 提交实验；确认内容和快照冻结，普通成员不能批准。
9. 导师要求修改；确认原 revision 与反馈保留、自动出现下一 EDITABLE revision；成员修改并重新提交。
10. 导师批准并发布；确认发布版可按固定模板版本和快照复现。
11. 从发布记录创建 PREPARING 项目；确认操作者 OWNER、转换响应与项目详情均保留来源关系，且重复转换不重复建项目。
12. 以非项目成员和 GUEST 验证 404/403/401；检查审计含操作者、目标、动作、状态、requestId 和时间。
13. 前端关闭 mock 跑完整流程，检查三视口和全部 UI 状态。
