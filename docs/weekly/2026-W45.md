## 1. 一句话目标与价值

让成员提交包含多种元器件的采购单，经条件审批或自动免审后登记下单，并由库存管理员分多批确认到货；每次确认都原子地产生到货事实、库存批次和库存增加流水，重复、超量、越权或事务失败均不能造成重复库存或半完成数据。

## 3. 本周业务闭环

```text
创建 DRAFT 采购单与多条元器件明细
→ 服务端计算金额并提交
→ 普通小额自动写 AUTO_APPROVED，或进入 PENDING_APPROVAL
→ 人工批准/拒绝
→ 登记供应商、平台订单号、购买人和实付并标记 ORDERED
→ 创建一张到货草稿
→ 确认到货
→ 同事务生成库存批次、库存增加流水、更新余额和采购进度
→ 重复多批直到 RECEIVED，或取消未到剩余量
→ COMPLETED
```

附件路径独立且可选：

```text
采购单 → 订单截图 / 发票 mediaId
到货记录 → 到货照片 / 包装照片 mediaId
```

无附件不阻止提交、审批、下单、确认到货或完成。

## 4. 必须分离的对象

1. 采购策略版本：决定提交时审批门槛。
2. 采购单：流程、金额、供应商和项目关联。
3. 采购明细：元器件、规格版本、数量、单价和到货进度。
4. 审批记录：自动/人工决策和策略快照。
5. 到货记录：一次物理到货确认。
6. 到货明细：本批各采购明细的实际数量和批次属性。
7. 库存批次：可供后续领用追溯的库存事实。
8. 库存增加流水：不可变的数量变化事实。
9. 库存余额：可从批次/流水重建的查询投影。
10. 发票及采购附件：mediaId 与采购 owner 的受控关联。

不得创建一个模糊的“采购入库表”替代以上边界，也不得用采购状态推算库存现量。

## 5. D1-D10 推荐决策（待确认）

| 决策 | 推荐方案 | 主要取舍 |
|---|---|---|
| D1 | 全局版本化策略；普通采购 payableAmount < 500.00 CNY 免审，等于或超过需审 | 简单可配、历史可解释；暂不做项目级阈值 |
| D2 | 单价 ≥1000.0000 CNY 或策略指定分类（含后代）强制审批 | 不污染元器件分类，不依赖自由文本/AI |
| D3 | DRAFT/PENDING_APPROVAL/APPROVED/ORDERED/PARTIALLY_RECEIVED/RECEIVED/COMPLETED + REJECTED/CANCELED | 与总体规格一致，免审仍写 AUTO_APPROVED |
| D4 | purchaseNo 服务端生成；平台+平台订单号非空唯一；供应商保存快照，不建主数据 | 防重复订单，控制 W45 范围 |
| D5 | 仅 CNY；数量3位、单价/单位成本4位、金额2位；HALF_UP；按行比例分摊运费优惠 | 成本可追溯，避免浮点与各端重算 |
| D6 | 项目可选；OWNER/MAINTAINER附加可见，不获得审批或入库权 | 复用项目 ACL，不扩大高风险动作 |
| D7 | 多批到货、超量容差0；已确认不可撤回；允许显式取消全部未到剩余量 | 保证库存不超收，不伪造退货 |
| D8 | 一条到货明细一个库存批次；保存成本、供应商批号、生产/到期和备注 | 未来领用/BOM 可追到真实来源 |
| D9 | 四种 purpose；JPEG/PNG、5 MiB；订单/发票各5张，到货/包装合计10张；附件可选 | 完全复用 W44 安全媒体能力，PDF延期 |
| D10 | 实现拒绝、下单前取消、无到货整单取消和部分到货取消剩余；退货/退款延期 | 避免本周引入负库存和财务逆向流 |

确认前契约和索引保持 REVIEW；不得创建 V13、后端采购业务代码或前端采购页面。

## 11. 验收脚本与逐步方法

自动化入口：`scripts/acceptance/w45-procurement-receiving-integration.ps1`。

计划执行：

```powershell
# 账号通过参数或 USN_W45_* 环境变量提供，不写入仓库：
pwsh ./scripts/acceptance/w45-procurement-receiving-integration.ps1 `
  -BaseUrl http://localhost:8080 `
  -ComponentId 301
```

验收必须逐步证明：

1. MEMBER 创建包含两条元器件的 DRAFT，服务端金额正确。
2. 相同幂等键同请求精确重放；换内容返回 409。
3. 小额普通采购自动通过并写 AUTO_APPROVED。
4. 达金额/贵重/分类条件进入 PENDING_APPROVAL；本人不能审批，TEACHER/SYSTEM_ADMIN 非本人可批准。
5. STOCK_KEEPER 登记下单；重复平台订单号返回 409。
6. 第一批部分到货确认后生成唯一 batch/movement，采购变 PARTIALLY_RECEIVED，余额只增加一次。
7. 同确认请求精确重放不重复增加；新 key 重复确认返回冲突。
8. 超量到货整事务失败，其他明细和库存均不变化。
9. 受控故障点使确认返回 500，receipt 仍 DRAFT、无批次/流水/余额变化。
10. 第二批到货后进入 RECEIVED，再完成为 COMPLETED。
11. MEMBER 越权确认到货返回 403；无关 MEMBER 查询采购/发票返回 404。
12. 上传订单截图/发票/到货照片返回 mediaId 且无基础设施字段；附件为空不阻止入库。
13. 空列表、部分到货、冲突、权限、附件不可见和移动端展示均符合契约。

真实 API 未实现前只检查脚本语法，不把计划步骤写成联调通过。
