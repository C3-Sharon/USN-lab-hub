## 1. 一句话目标与价值

让实验室能够录入、查询、编辑、停用和恢复一个来源可解释的元器件型号，经人工确认外部规格后形成不可变正式快照，并在有图和无图两种情况下都稳定展示。

## 3. 本周主流程

### 3.1 手工建档

```text
维护分类与制造商
→ 创建元器件 DRAFT
→ 来源不可用时人工录入规格并说明依据
→ 生成正式规格快照
→ 激活为 ACTIVE
→ 普通成员可查询
```

### 3.2 外部候选确认

```text
创建元器件 DRAFT
→ 人工登记来源 URL、来源类型、获取时间、原始规格和标准化建议
→ STOCK_KEEPER / SYSTEM_ADMIN 对比并修正
→ 人工确认生成不可变规格快照
→ 激活进入正式目录
```

### 3.3 图片与占位

```text
型号无图 → 返回确定性 placeholderKey
可选上传 JPEG/PNG → 返回稳定 mediaId 和受控元数据
替换 → 新 mediaId，旧媒体逻辑删除
删除最后一图 → 自动回到同一确定性占位
```

## 5. 已确认的 D1-D9

1. 分类/制造商/型号分表，型号状态 DRAFT/ACTIVE/INACTIVE，关键规格走快照。
2. `(manufacturerId, normalizedMpn)` 全状态唯一；分类最多三级；只停用/恢复，不物理删除。
3. SYSTEM_ADMIN/STOCK_KEEPER 可写，TEACHER 全局只读，MEMBER 只读 ACTIVE。
4. 外部候选保存来源 URL/类型/获取时间、原始值和标准化建议；W44 不自动抓取 URL。
5. 候选必须人工确认；来源不可用时允许 MANUAL 快照且 sourceNote 必填。
6. 正式规格快照追加写、不可变，确认使用 component/candidate version 和 Idempotency-Key。
7. 每型号最多 5 图、JPEG/PNG、5 MiB、4096×4096；替换新 mediaId、删除逻辑化、无图占位。
8. 所有 POST 命令动作使用幂等键，更新/状态动作同时使用 version；冻结 401/403/404/409。
9. 页码分页；分类/状态/厂商/封装/单位筛选，MPN/名称/厂商搜索和排序白名单。

用户于 2026-10-29 明确确认 D1-D9，契约与索引升级为 FROZEN。产品 PR 合入 `dev` 后，后端与前端才可从最新 `dev` 开工；在真实实现和联调完成前，不得把本周能力写入 CURRENT_STATE。

## 10. 真实验收脚本

契约验收脚本：`scripts/acceptance/w44-component-catalog-integration.ps1`。

计划执行：

```powershell
# 在本机设置以下环境变量，值不得写入仓库或 PR：
# USN_W44_ADMIN_MEMBER_ID / USN_W44_ADMIN_PASSWORD
# USN_W44_MEMBER_MEMBER_ID / USN_W44_MEMBER_PASSWORD
pwsh ./scripts/acceptance/w44-component-catalog-integration.ps1 `
  -BaseUrl http://localhost:8080
```

覆盖：

1. 管理员创建分类、制造商和型号草稿。
2. 相同幂等键与相同请求精确重放；相同键换内容返回 409。
3. 同制造商重复 MPN 返回 409。
4. MEMBER 创建/修改返回 403，查询 DRAFT 返回 404。
5. 使用过期 version 更新返回 409，原数据不被覆盖。
6. 登记外部候选，确认后生成规格快照 v1。
7. 来源不可用时手工录入，生成快照 v2，v1 仍可查询。
8. 激活后 MEMBER 可查询正式目录。
9. 无图时 placeholderKey 稳定。
10. 上传 PNG 后返回 mediaId，不返回任何基础设施字段。
11. MEMBER 可读取 ACTIVE 型号媒体元数据和内容；删除后元数据与内容均返回 404。
12. 删除最后图片后回到相同 placeholderKey。
13. GUEST 返回 401，错误包含 `data.traceId`。

真实 API 尚未实现前只做 PowerShell 语法检查，不把脚本计划冒充联调通过。
