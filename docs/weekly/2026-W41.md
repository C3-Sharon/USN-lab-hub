## 3. 现状与矛盾

1. **学习实验台与项目工作台需要明确区分** — 首页 learning 区域目前为 NOT_AVAILABLE，本周切换为 READY。需要通过导航、术语和视觉区分学习实验和正式项目。

4. **幂等语义** — 重复开始学习和重复标记单元完成必须明确处理。

## 4. 用户场景

### 场景 1：老师发布零基础学习路线

TEACHER 创建学习路线（DRAFT）→ 添加阶段和学习单元 → 发布路线（PUBLISHED）→ 普通成员可见。

### 场景 2：成员浏览路线并开始学习

MEMBER 登录 → 首页 learning 区域显示空状态 → 点击"浏览学习路线" → 路线列表页 → 选择"嵌入式硬件入门" → 查看阶段结构 → 点击"开始学习" → 首页 learning 区域更新。

### 场景 3：成员标记单元完成

MEMBER 进入路线详情 → 勾选完成的单元 → 进度条更新 → 全部单元完成时路线状态自动转为 COMPLETED。

### 场景 4：重复开始学习

MEMBER 再次点击"开始学习" → 返回 200，不创建重复记录（幂等）。

### 场景 5：未发布路线对普通成员不可见

TEACHER 创建 DRAFT 路线 → MEMBER 请求列表 → 列表中不含 DRAFT 路线 → MEMBER 直接访问 DRAFT 路线 → 返回 404。

### 场景 6：归档路线

SYSTEM_ADMIN 将已发布路线归档 → 已有学习记录保留 → 不可开始新学习 → 返回 409 LEARNING_ARCHIVED。

### 场景 7：空路线

路线无任何阶段或单元 → totalUnitCount=0 → 不可标记完成 → progress=0。

## 5. 已冻结内容（FROZEN）

### 5.1 路线状态三档

DRAFT / PUBLISHED / ARCHIVED（ARCHIVED 为终态）

### 5.2 学习状态三档

NOT_STARTED / IN_PROGRESS / COMPLETED

### 5.3 进度计算

- `progress = completedUnitCount / totalUnitCount * 100`（向下取整）
- 空路线 progress=0
- 由后端计算，前端不得伪造

### 5.4 幂等语义

- 重复开始学习：返回 200，返回已有记录
- 重复标记单元完成：返回 200，不创建重复记录
- 重复取消单元完成：返回 200

### 5.5 权限矩阵

- SYSTEM_ADMIN / TEACHER：创建/编辑路线、阶段、单元；更新路线状态
- MEMBER / STOCK_KEEPER：查看已发布路线、开始学习、标记/取消单元完成
- GUEST：不可访问学习域

### 5.6 首页 learning 区域

- state: NOT_AVAILABLE → READY
- inProgressCount + completedCount + list（最近 3 条）
- 独立降级，不影响其他区域

### 5.7 API 接口（14 个）

- 路线：POST / GET 列表 / GET 详情 / PUT 编辑 / PUT status
- 阶段：POST / GET 列表 / PUT 编辑
- 单元：POST / PUT 编辑
- 成员学习：POST enroll / POST complete / DELETE complete / GET my-roadmaps

### 5.8 错误响应

- 400：INVALID_PARAMETER、LEARNING_NOT_ENROLLED
- 403：LEARNING_OPERATION_DENIED、ACCESS_DENIED
- 404：LEARNING_ROADMAP_NOT_FOUND、LEARNING_STAGE_NOT_FOUND、LEARNING_UNIT_NOT_FOUND
- 409：LEARNING_INVALID_TRANSITION、LEARNING_ARCHIVED、LEARNING_EMPTY_ROADMAP

## 8. 最终确认结论

### 后端

1. 路线标题和阶段名称不设业务唯一约束；sortOrder 为非负整数，默认 0。
2. progress 向下取整；最后一个单元完成时自动写 completedAt，取消后回退为 IN_PROGRESS 并清空 completedAt。
3. 学习记录使用 `(roadmap_id, user_id)` 唯一约束，单元完成记录使用 `(unit_id, user_id)` 唯一约束，以数据库约束和事务保证幂等。
4. Flyway V9 新增五张学习域表并预置“嵌入式硬件入门”路线，不修改既有迁移。
5. totalUnitCount 按当前结构动态计算；已发布路线新增单元时，在同一事务内校准既有进度和完成状态。
6. TEACHER 可管理全部学习路线。
7. 阶段列表中的每个单元返回当前登录用户维度的 `completed`；未加入路线或无完成记录时为 false。

### 前端

1. 1440px 三列、1280px 两列、390px 单列；详情采用垂直阶段时间线。
2. 单元勾选立即提交，失败时回滚显示；进度只消费后端值。
3. 使用线性进度条、确定性标题首字封面占位和统一空状态。
4. 桌面端阶段默认展开，移动端默认折叠；继续学习定位到首个未完成阶段。
5. 学习域使用小面积紫色语义识别和 Reading 图标，与项目工作台保持并列且清晰区分。

完整字段、事务语义和响应样例以 `docs/contracts/LEARNING_EXPERIMENT_API.md` 第 10 节为准。

## 10. 联调验收脚本（8 步）

### 前置条件
- 后端服务运行在 localhost:8080
- 前端运行在 localhost:5173
- MySQL 8 运行，Flyway 已迁移到 V9
- 已有 SYSTEM_ADMIN 账号 admin/admin123
- 已有 MEMBER 账号 student01/123456
- 预置零基础路线（PUBLISHED）

### 步骤 1：老师发布路线
```bash
# admin 确认预置路线已 PUBLISHED
curl -s http://localhost:8080/api/learning/roadmaps?status=PUBLISHED \
  -H "Authorization: Bearer $ADMIN_TOKEN"
# 断言：返回 200，list 包含"嵌入式硬件入门"
```

### 步骤 2：成员浏览路线
```bash
# student01 浏览已发布路线
curl -s http://localhost:8080/api/learning/roadmaps \
  -H "Authorization: Bearer $STUDENT_TOKEN"
# 断言：返回 200，list 包含已发布路线，不含 DRAFT
```

### 步骤 3：成员查看阶段结构
```bash
# student01 查看路线详情
curl -s http://localhost:8080/api/learning/roadmaps/1 \
  -H "Authorization: Bearer $STUDENT_TOKEN"
# 断言：返回 200，stages 包含阶段和单元
```

### 步骤 4：成员开始学习
```bash
# student01 开始学习
curl -s -X POST http://localhost:8080/api/learning/roadmaps/1/enroll \
  -H "Authorization: Bearer $STUDENT_TOKEN"
# 断言：返回 200，status=NOT_STARTED，progress=0
```

### 步骤 5：首页 learning 区域更新
```bash
# student01 首页
curl -s http://localhost:8080/api/workbench/overview \
  -H "Authorization: Bearer $STUDENT_TOKEN"
# 断言：learning.state=READY，list 包含该路线
```

### 步骤 6：重复开始学习（幂等）
```bash
# student01 再次开始学习
curl -s -X POST http://localhost:8080/api/learning/roadmaps/1/enroll \
  -H "Authorization: Bearer $STUDENT_TOKEN"
# 断言：返回 200，不创建重复记录
```

### 步骤 7：标记单元完成
```bash
# student01 标记第一个单元完成
curl -s -X POST http://localhost:8080/api/learning/units/1/complete \
  -H "Authorization: Bearer $STUDENT_TOKEN"
# 断言：返回 200，roadmapProgress.progress > 0
```

### 步骤 8：未发布路线不可见
```bash
# admin 创建 DRAFT 路线
curl -s -X POST http://localhost:8080/api/learning/roadmaps \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"title":"测试草稿路线","status":"DRAFT"}'
# 记录 id

# student01 尝试访问 DRAFT 路线
curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/api/learning/roadmaps/$DRAFT_ID \
  -H "Authorization: Bearer $STUDENT_TOKEN"
# 断言：返回 404
```
