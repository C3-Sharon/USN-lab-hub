# 2026-W38 周任务：全局角色、权限与个人工作台契约

> 路线周次：第 2 周
> 风险：HIGH（权限 + 鉴权 + 首页聚合，涉及安全边界）
> 状态：REVIEW

## 1. 本周目标

把当前 `admin/student` 两级角色升级为五档全局角色，统一鉴权 Header 和 401/403 错误格式，冻结个人工作台首页聚合接口与信息层级。不同角色登录后看到正确的首页区域和数据范围。本周只冻结契约，不实现项目成员、项目角色或新的业务模块。

## 2. 明确不做

- 不实现项目成员和项目角色（第 3 周）
- 不实现项目、任务、学习域的真实数据
- 不实现库存权限业务（第 9-10 周）
- 不实现动态二维码、请假或补签
- 不平台化多设备 IoT
- 不引入 Spring Security、OAuth 或微服务
- 不修改 MQTT、库存、RAG 或 Agent 契约
- 不把未开放模块做成 mock 数据冒充真实能力

## 3. 用户与场景

### 3.1 目标用户

- **系统管理员**：管理账号、角色、系统配置，查看全部数据
- **老师/实验室负责人**：查看全部项目、人员、资源和考勤统计
- **库存管理员**：采购入库、库存盘点、条件审批（第 9 周起生效）
- **普通成员**：考勤、学习实验、参与项目、申请资源
- **访客**：仅访问显式公开页面，不需要登录

### 3.2 主流程

1. 用户访问登录页，输入学工号 + 密码
2. 登录成功，返回 JWT Token + 用户信息 + 考勤信息 + 角色
3. 跳转个人工作台首页，加载聚合数据
4. 根据角色显示对应区域和菜单
5. 点击签到/签退，更新考勤状态

### 3.3 失败/越权流程

- Token 缺失或无效 → 401 → 前端清除登录态，跳转登录页
- Token 有效但权限不足 → 403 → 前端显示"无权访问"，不跳转登录
- 首页部分区域失败 → 该区域显示错误 + 重试，不影响其他区域
- 用户被禁用 → 下次登录返回 401，msg："账号已被禁用"

### 3.4 前置数据

- dev 分支 commit `6ba9972`
- 现有 `sys_role` 表：admin、student 两档
- 现有 JWT 拦截器：仅覆盖 `/usnhub/**`，读 `token` Header
- 现有首页：仅考勤模块有真实数据
- 现有 IoT 演示项目：PM-001 单设备闭环

## 4. 现状矛盾与决策

| 矛盾 | 现状 | 决策 |
|---|---|---|
| 角色档数 | DB 只有 admin/student | 扩展为五档（SYSTEM_ADMIN/TEACHER/STOCK_KEEPER/MEMBER/GUEST），兼容旧值 |
| Header 名称 | 配置写 Authorization，拦截器读 `token` | 统一为 `Authorization: Bearer`，兼容旧 `token` Header 至第 4 周 |
| 前端双发 Header | 同时发 Authorization 和 token | 第 2 周保留双发，第 4 周移除 token |
| 拦截范围 | 仅 `/usnhub/**` | 扩展到 `/admin/**` 和需要鉴权的 `/api/**` |
| 前端角色守卫 | 只有 `meta.role === 'admin'` | 扩展为 roles 数组，支持多角色判断 |
| 首页内容 | 只有考勤 | 聚合考勤 + 模块占位（未开放显示"尚未开放"） |
| 访客角色 | 未显式定义 | 定义为未登录状态，只能访问显式公开页面 |
| 指令下发权限 | 当前所有登录用户都能下发 | 限制为 SYSTEM_ADMIN 和 TEACHER |

## 5. 冻结的契约

### 5.1 全局角色枚举

五档全局角色：SYSTEM_ADMIN（系统管理员）、TEACHER（老师/实验室负责人）、STOCK_KEEPER（库存管理员）、MEMBER（普通成员）、GUEST（访客）。详细定义见 `docs/contracts/AUTH_WORKBENCH_V1.md` §3。

旧 `admin` → `SYSTEM_ADMIN`，旧 `student` → `MEMBER`，兼容至少到第 4 周。

### 5.2 权限矩阵

页面可见性、数据范围和操作权限见 `AUTH_WORKBENCH_V1.md` §4。第 2 周关键变化：
- 指令控制台只对 SYSTEM_ADMIN 和 TEACHER 开放
- 成员管理和考勤管理只对 SYSTEM_ADMIN 和 TEACHER 开放
- 普通成员仍可查看 IoT 演示项目和设备（只读）

### 5.3 鉴权 Header 与错误响应

- 标准 Header：`Authorization: Bearer <token>`
- 兼容 Header：`token: <token>`（第 4 周移除）
- 401：HTTP 401 + `code: 401` + "登录状态已失效，请重新登录"
- 403：HTTP 403 + `code: 403` + "无权访问该资源"

### 5.4 首页聚合接口

- 路径：`GET /api/workbench/overview`
- 单接口聚合，不拆多个
- 区域：attendance、projects、tasks、learning、notifications、deviceReminder
- 每个区域有 `available` 字段标记是否已开放
- 第 2 周只有 attendance 和 deviceReminder 是真实数据

### 5.5 页面状态

loading / success / empty / error / permission / offline 六态，见 `AUTH_WORKBENCH_V1.md` §9。

### 5.6 三视口信息层级

1440x900、1280x800、390x844 三档固定视口。桌面双列布局，移动单列堆叠。详见 `AUTH_WORKBENCH_V1.md` §10。
