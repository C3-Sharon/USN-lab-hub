## 1. 本周目标

把当前 `admin/student` 两级角色升级为五档全局角色，统一鉴权 Header 和 401/403 错误格式，冻结个人工作台首页聚合接口与信息层级。不同角色登录后看到正确的首页区域和数据范围。本周只冻结契约，不实现项目成员、项目角色或新的业务模块。

## 3. 用户与场景

### 3.1 目标用户

- **系统管理员**：管理账号、角色、系统配置，查看全部数据
- **老师/实验室负责人**：查看全部项目、人员、资源和考勤统计
- **库存管理员**：采购入库、库存盘点、条件审批（第 9 周起生效）
- **普通成员**：考勤、学习实验、参与项目、申请资源
- **访客**：仅访问显式公开页面，不需要登录，不入库

### 3.2 主流程

1. 用户访问登录页，输入学工号 + 密码
2. 登录成功，返回 JWT Token + 用户信息（roles 数组 + primaryRoleKey）+ 考勤信息
3. 跳转个人工作台首页，加载聚合数据
4. 根据 roles 数组过滤侧栏菜单，显示对应首页区域
5. 点击签到/签退，更新考勤状态

### 3.3 失败/越权流程

- Token 缺失 → 401 reason=TOKEN_MISSING → 前端清除登录态，跳转登录页
- Token 无效（签名错误、双 Header 不一致） → 401 reason=TOKEN_INVALID → 清除登录态，跳转登录页
- Token 过期 → 401 reason=TOKEN_EXPIRED → 清除登录态，跳转登录页
- 账号禁用 → 401 reason=ACCOUNT_DISABLED → 清除登录态，跳转登录页，显示禁用提示
- 权限不足 → 403 reason=ACCESS_DENIED → 显示"无权访问"，不跳转登录
- 首页 attendance 失败 → 整个首页 error 态 + 重试
- 首页其他区域失败 → 该区域 ERROR 态 + 重试，不影响其他区域

## 4. 现状矛盾与决策

| 矛盾 | 现状 | 决策 |
|---|---|---|
| 角色档数 | DB 只有 admin/student | 保留 role_id=1/2，直接更新 role_key 为 SYSTEM_ADMIN/MEMBER，只新增 TEACHER/STOCK_KEEPER |
| 多角色关系 | sys_user_role 多对多 | 登录响应和首页用 roles 数组，primaryRoleKey 用于展示；JWT 鉴权查库不取 Token 声明 |
| Header 名称 | 配置写 Authorization，拦截器读 `token` | 统一为 `Authorization: Bearer`，兼容旧 `token` Header 至第 4 周；两者不一致返回 401 |
| 前端双发 Header | 同时发 Authorization 和 token | 第 2 周保留双发，第 4 周移除 token |
| 拦截范围 | 仅 `/usnhub/**` | 扩展到 `/usnhub/**`、`/admin/**`、需要鉴权的 `/api/**`；明确放行清单 |
| /admin/** 路径 | 独立于 /api/ | 本周不迁移到 /api/admin/**，保持现有路径 |
| SSE 鉴权 | 前端 EventSource 无法附加 Header | 保留 `/api/iot/public/**` SSE 为公开只读，不被 /api/** 拦截误伤 |
| 前端角色守卫 | 只有 `meta.role === 'admin'` | 扩展为 meta.roles 数组，支持多角色判断 |
| 首页内容 | 只有考勤 | 聚合考勤 + 模块占位（未开放显示"尚未开放"）；state 三态区分未开放和调用失败 |
| 访客角色 | 未显式定义 | 定义为未登录状态，只能访问显式公开页面，不入库 |
| 指令下发权限 | 当前所有登录用户都能下发 | 暂时仅限 SYSTEM_ADMIN（历史演示兼容，待平台化后重新设计） |
| 禁用用户 Token | 无明确策略 | 立即失效，后端每次鉴权查用户状态；本周不引入 Redis 黑名单 |
| 401/403 细分 | 只有统一 msg | 增加 reason/errorCode 枚举，前端展示文案可统一但逻辑可区分 |
| 账号管理权限 | 未明确 | 新增/编辑/停用成员 + 角色管理仅 SYSTEM_ADMIN |

## 5. 冻结的契约

### 5.1 全局角色枚举

五档全局角色：SYSTEM_ADMIN（系统管理员）、TEACHER（老师/实验室负责人）、STOCK_KEEPER（库存管理员）、MEMBER（普通成员）、GUEST（访客）。详细定义见 `docs/contracts/AUTH_WORKBENCH_V1.md` §3。

**迁移方案**：保留 role_id=1/2 不变，直接 UPDATE role_key 为 SYSTEM_ADMIN/MEMBER，只 INSERT TEACHER 和 STOCK_KEEPER。GUEST 不创建数据库角色，是逻辑角色。

**多角色**：sys_user_role 多对多；roles 数组为正式字段，primaryRoleKey 用于展示；旧 role/roleKey 字段兼容至第 4 周。

**JWT 鉴权**：不依赖 Token 中存储的角色声明，每次鉴权从数据库查询当前用户的有效角色列表和状态。

### 5.2 权限矩阵

页面可见性、数据范围和操作权限见 `AUTH_WORKBENCH_V1.md` §6。第 2 周关键变化：

- 成员管理（新增/编辑/停用）和角色管理仅 SYSTEM_ADMIN
- 成员列表和考勤管理对 SYSTEM_ADMIN 和 TEACHER 开放（TEACHER 只读）
- 硬件指令下发暂时仅限 SYSTEM_ADMIN
- TEACHER 不能只凭全局角色获得账号停用或硬件调控权限
- 普通成员仍可查看 IoT 演示项目和设备（只读）

### 5.3 鉴权 Header 与错误响应

- 标准 Header：`Authorization: Bearer <token>`
- 兼容 Header：`token: <token>`（第 4 周移除）
- 双 Header 值不一致 → 401
- 拦截范围：`/usnhub/**`（登录除外）、`/admin/**`、`/api/**`（公开接口除外）
- 放行清单：登录接口、OPTIONS、`/api/iot/public/**`、`/iot/public`、`/login`
- 401：HTTP 401 + code + msg + reason（TOKEN_MISSING/TOKEN_INVALID/TOKEN_EXPIRED/ACCOUNT_DISABLED）
- 403：HTTP 403 + code + msg + reason（ACCESS_DENIED/RESOURCE_NOT_FOUND）
- 禁用用户：立即失效，每次鉴权查库，本周不引入 Redis 黑名单

### 5.4 首页聚合接口

- 路径：`GET /api/workbench/overview`
- 单接口聚合，不拆多个
- 六区域：attendance、projects、tasks、learning、notifications、deviceReminder
- 每个区域有 `state` 字段三态：READY / NOT_AVAILABLE / ERROR
- ERROR 态附加 errorCode、message、retryable
- `state` 是区域可用性和调用结果的唯一状态字段，不增加或依赖 `available`
- 第 2 周只有 attendance 和 deviceReminder 是真实数据（state: READY）
- 部分失败：attendance 失败 → 整个首页 error；其他区域独立降级
- 登录响应中的 attendance 仅用于兼容旧客户端；登录后首页以本接口的 attendance 为权威数据

### 5.5 页面状态

loading / success / empty / error / permission / offline 六态，见 `AUTH_WORKBENCH_V1.md` §9。

### 5.6 三视口信息层级

1440x900、1280x800、390x844 三档固定视口。桌面双列布局，移动单列堆叠。详见 `AUTH_WORKBENCH_V1.md` §10。
