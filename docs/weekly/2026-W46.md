## 1. 一句话目标

普通成员能够申请领用元器件；普通、低价值且库存充足的申请自动批准并预占，贵重、库存紧张或超阈值申请进入人工审批，批准后由库存管理员准确发放扣减，拒绝、取消或超时安全释放预占，所有库存变化通过不可变流水追溯且并发永不超扣。

## 3. 本周业务闭环

```text
创建 DRAFT 领用申请
→ 提交时锁库存并按批次规则分配
→ 创建 ACTIVE 库存预占
→ AUTO_APPROVED 或 PENDING_APPROVAL
→ 批准保留预占；拒绝/取消/超时释放预占
→ STOCK_KEEPER 确认发放
→ 同事务消费预占、扣减批次和余额、写 ISSUE_OUT
→ 未使用物料按原批次受控 RETURN_IN
→ 损耗/报废只能扣可用未预占数量并写流水
```

核心不变量：

```text
availableQuantity = onHandQuantity - reservedQuantity
onHand >= reserved >= 0
预占不改变 onHand
发放才减少 onHand/current 并写 ISSUE_OUT
拒绝/取消/超时只释放 reserved，不写库存数量流水
```

## 6. D1-D12 待确认决策

| 决策 | 推荐方案 | 主要取舍 |
|---|---|---|
| D1 | 所有提交先预占；总值≥100、批次单价≥500、指定分类、数量超限或预占后低于20%触发人工审批 | 规则可解释；阈值待负责人确认 |
| D2 | 全局追加写策略版本，提交冻结触发快照 | 历史可复现，不追溯重算 |
| D3 | DRAFT/PENDING_APPROVAL/APPROVED/REJECTED/ISSUED/CANCELED/EXPIRED | 无模糊部分态 |
| D4 | 审批与实际发放分离；审批不扣库存，发放才写 ISSUE_OUT | 避免批准冒充实物交付 |
| D5 | W46 只做全量原子发放/整单取消，不做部分发放或部分取消 | 降低半完成与并发复杂度 |
| D6 | FEFO 优先、其余 FIFO；允许库存管理员发放前原子重分配 | 临期优先且保留人工纠偏 |
| D7 | 提交时预占，默认72小时；审批不延长；定时+惰性安全释放 | 防长期占库；期限待确认 |
| D8 | 库存紧张按预占后 available/onHand<20%；component 可覆盖直接数量上限 | 不新增可编辑安全库存事实 |
| D9 | TEACHER/SYSTEM_ADMIN 审批；STOCK_KEEPER/SYSTEM_ADMIN 发放；申请人不得审批或发放本人申请 | 职责分离 |
| D10 | W46 实现 RETURN_IN、LOSS_OUT、SCRAP_OUT；均关联原批次和不可变流水 | 回收 W45 延期项但不做采购退款 |
| D11 | STOCKTAKE_ADJUSTMENT 只冻结语义，第12周实现盘点单、差异复核与双人确认 | 防止通用调整变成直接改库存 |
| D12 | projectId 可选；OWNER/MAINTAINER只扩展可见性，普通成员不看成本和采购来源 | 复用项目 ACL，不扩大库存权限 |

上述任一项未确认，契约继续 REVIEW。
