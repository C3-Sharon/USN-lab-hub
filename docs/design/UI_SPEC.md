# USN Lab Hub UI 实施规范

## 1. 视觉定位

关键词：实验室工作台、电子工程、可靠、可扫描、克制。比例为 85% 操作型工作台与 15% 硬件辨识元素。页面首先服务考勤、项目、实验、库存和设备操作，其次才表达品牌。

参考图：

- `docs/design/reference/personal-workbench-v1.png`
- `docs/design/reference/usn-lab-emblem-reference.png`

实验室标志提供的艺术元素：蓝色“感知”、紫色“互联”、双向弧线/波纹、圆环连接、USN 字标。使用这些元素作为小面积状态或品牌线索，不把整页做成蓝紫渐变。

```css
  --usn-radius-sm: 4px;
  --usn-radius-md: 8px;
  --usn-shadow-panel: 0 1px 2px rgba(23, 33, 43, 0.08);

```

- 正文字号 14px，辅助文字 12px，页面标题 22-28px，面板标题 16-18px。
- 字号不随视口宽度缩放，字距为 0。
- 页面间距以 4px 为基准，常用 8/12/16/24/32px。
- 内容最大宽度 1600px；桌面侧栏 224px，折叠 64px；顶栏 56px。
- 卡片圆角最大 8px，阴影只分离真实面板，不做漂浮装饰。

## 3. 应用外壳

- 左侧：实验室标志、一级模块、当前用户权限可见项。
- 顶部：页面标题/面包屑、全局搜索入口、通知、用户菜单。
- 主区：浅灰画布上的全宽工作区域，按信息层级分带，不把整区套大卡片。
- 个人工作台首屏按“考勤与提醒、进行中项目、本周任务、学习/审批/设备摘要”排列。
- 知识助手为右侧可收起面板或上下文入口，默认不覆盖主工作区。

## 4. 组件规则

- 操作按钮：明确命令使用图标+短文本；纯工具操作优先熟悉图标并提供 tooltip。
- 状态：短标签只用于在线、审批、风险、项目状态；不要把所有元数据做成胶囊。
- 表格：固定操作列，长文本省略并可查看全文，金额/数量右对齐，状态不只依赖颜色。
- 筛选：高频条件平铺，低频条件进入更多筛选；移动端使用抽屉。
- 表单：按业务组分段，必填和错误就近显示；上传图片不是默认必填。
- 模态框：只用于短确认和小表单；复杂创建/编辑使用独立页或抽屉。
- 进度圆环只用于项目进度或设备健康；感知波纹只用于实时设备状态。

## 5. 图片与默认占位

允许项目、元器件、采购/到货、资产、硬件版本、板卡实例、实验和维修上传图片。创建和入库不能因没有图片而阻塞。

占位由前端静态组件生成：

- 项目：类别图标、项目代号和一条品牌蓝侧边。
- 元器件：封装轮廓、分类图标、型号首字符。
- 硬件版本：PCB 网格、版本号、研发/打板/装配状态。
- 资产：设备类别图标、资产编号和可借/维修状态。
- 采购：订单图标、供应商首字和到货状态。

同一对象的占位必须稳定，不在运行时请求 AI 生成。缩略图容器使用固定宽高比，图片加载失败自动回退占位，不能撑动布局。

## 6. 禁止的 GPT 式模式

- 蓝紫渐变铺满背景或大标题。
- 巨大“欢迎来到未来实验室”Hero。
- 发光边框、玻璃拟态、漂浮渐变球和无意义插画。
- 每个数字单独做大圆角卡片，卡片再嵌套卡片。
- 助手聊天框占据默认首页中心。
- 用长段说明文字解释按钮、快捷键或页面功能。
- 只有漂亮正常态，没有空、失败、权限和离线状态。

## 7. 响应式验收

固定视口：`1440x900`、`1280x800`、`390x844`。

桌面端检查侧栏、主区比例、表格密度和抽屉遮挡；移动端侧栏变抽屉，双栏改单栏，表格改卡片摘要或横向滚动，主要按钮保持可达。所有视口必须检查最长中文字段、金额、订单号、硬件版本号和错误文案。

每个关键页面 PR 提交：正常态、空状态、错误或权限状态截图。个人工作台第一版必须对照参考图人工修正至少一轮。

## 8. 给前端 Agent 的页面 Prompt 模板

```text
请实现 USN Lab Hub 的【页面名称】。先读取 AGENTS.md、UI_SPEC.md、当前周文档、相关契约和参考图。

产品场景：【用户、目标、主流程】
数据契约：【文件路径与接口】
必须状态：【loading/empty/error/permission/success/offline 等】
必须区域：【按优先级列出】
明确不做：【本周范围外】

视觉必须是克制的实验室操作工作台：使用 UI_SPEC Token，蓝色主交互，紫色仅知识/Agent；卡片圆角不超过 8px；无营销 Hero、玻璃拟态、发光、渐变大标题、嵌套卡片。图片可选，无图使用按对象类型确定的占位组件。

先实现数据适配和状态，再实现页面。使用 Element Plus 和现有项目结构。完成后接真实 API，并在 1440x900、1280x800、390x844 检查截图。输出修改文件、测试/构建命令、截图路径、联调步骤、契约差异和未完成事项。
```

## 9. 无 Figma 工作流

参考图冻结方向，UI_SPEC 冻结规则，产品周文档冻结页面内容。前端先实现应用外壳和一个关键页面，截图评审通过后再扩展同类页面。Figma 可用于复杂流程或多人视觉评审，但不是实现高质量 UI 的前置条件；代码、Token、截图和组件状态才是仓库中的事实源。
