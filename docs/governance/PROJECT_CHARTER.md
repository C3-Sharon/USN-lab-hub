# USN Lab Hub 项目章程

> 生效日期：2026-08-19
> 建设周期：26 个开发周
> 团队：产品负责人、前端兼边缘工具负责人、Java 后端负责人

## 1. 产品使命

让小型高校硬件实验室用一个平台完成“人、学习、项目、物料、硬件、设备、知识”的持续记录与协作，并让每次采购、打板、装配、实验、设备数据和项目交接都能找到上下文。

平台既要能在实验室真实使用，也要形成可在简历和答辩中展示的完整工程：业务闭环可信、Java 技术点有真实场景、UI 有实验室辨识度、部署和测试证据可复现。

## 2. 六个月完整范围

1. 人员、角色、考勤、请假补签和个人工作台。
2. 项目档案、成员、里程碑、任务、动态、仓库、归档和交接。
3. 学习路线、实验模板版本、实验记录、导师反馈和项目转化。
4. 元器件目录、联网辅助录入、图片、规格和替代料确认。
5. 采购单、订单、金额、发票、分批到货、库存批次和库存流水。
6. 领用、退回、损耗、报废、盘点、条件审批和并发一致性。
7. 实验室资产独立编号、借还、维护和状态。
8. 自研硬件产品、版本、BOM、打板、裸板批次、装配、板卡实例和维修追溯。
9. 多设备 IoT 模板、动态指标、遥测、告警、指令、ACK、SSE 和模拟器。
10. 图片与文件可选上传、确定性占位、权限、缩略图和公开控制。
11. GitHub/GitLab 连接、摘要同步和 GitLab 离线降级。
12. 知识库持续 CRUD、审核、版本、增量摄取、删除恢复和 ACL。
13. Java Hybrid RAG、引用、Inspector、固定评测集和两个真实场景。
14. 学习、项目、元器件、诊断、受控硬件调控五种 Agent 模式。
15. 双 Spring Boot 实例、缓存、Outbox、监控、压测、备份和恢复。

## 3. 产品主轴

登录后默认进入个人工作台，首屏同时看见今日考勤、正在参与的项目、本周任务、学习实验、待处理事项和设备提醒。项目工作台是正式工作的主轴；学习实验台服务零基础成员从 STM32/ESP32、电路、焊接和 PCB 入门到可转化为项目草案的过程。

IoT 是硬件项目的可选增强能力，不是创建项目、硬件或资产的前提。图片同样可选；不上传时使用按对象类型确定的默认占位 UI。

## 4. 成功标准

完成必须同时满足：

- 总体规格第 19 节每一项均有可运行入口。
- 每项关联 PR、自动化测试或人工检阅、截图或报告、演示步骤。
- 三种真实硬件接入统一平台契约，其中至少一种支持受控指令闭环。
- 采购到入库再到装配扣料能够追溯到订单、库存批次、硬件版本和板卡实例。
- RAG 在元器件手册问答和设备故障诊断两个场景达到已冻结评测门槛。
- 干净环境可部署，双实例可运行，MySQL 和 MinIO 的备份恢复做过演练。
- 老师、普通成员和管理员都能在权限范围内完成自己的主流程。

## 5. 非目标

- 不建设完整 ERP、会计、付款对账和复杂报销。
- 不建设 Jira 级项目管理和强制敏捷流程。
- 不建设通用工业 IoT 低代码平台。
- 不用考勤时间自动评价成员贡献。
- 不强制所有对象连接 IoT 或上传图片。
- 不为简历观感提前拆微服务或引入 Kafka、Kubernetes、GraphRAG。
- 不让大模型直接生成 Topic/payload 并访问 Broker。

## 6. 约束

- 三人每周各工作 4-5 天，每天不超过 8 小时，建议每人 12-20 小时。
- 每角色每周一个有意义 PR；每四至五周形成一个稳定演示版本。
- GitHub 是唯一开发主线，GitLab 在实验室网络可用时单向同步。
- 后端保持 Spring Boot 模块化单体，JDK 17；前端保持 Vue 3 + Vite + Element Plus。
- 任何延期必须登记恢复周，不得静默把功能堆到最后两周。

## 7. 决策权

- 产品负责人冻结业务范围、术语、字段语义、权限和验收样例。
- 前端负责人决定符合 UI_SPEC 的组件落点、交互实现和边缘工具结构。
- 后端负责人决定符合总体架构的 Java 模块、事务、缓存和持久化实现。
- 跨角色契约需三人确认；高风险控制、库存一致性和权限边界不能由单人静默修改。
- 范围争议以总体规格和追踪矩阵为准，新增功能先写变更理由、代价和被替换工作。
