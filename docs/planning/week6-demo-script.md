# Week 6 Demo Script / 第六周正式演示脚本

USN Lab Hub IoT · 一个半月 MVP 成果演示

目标时长：10 分钟以内

---

## 1. 演示环境

| 组件 | 地址/命令 | 状态要求 |
|---|---|---|
| MQTT Broker | `localhost:1883` | 已启动，可连接 |
| MySQL | `localhost:3306/usn_lab_hub` | 已启动，V1 - V5 迁移完成 |
| 后端 | `http://localhost:8080` | 已启动，健康检查 200 |
| PM-001 模拟器 | `python scripts/pm001_simulator.py` | 已启动，每 5 秒上报 |
| 前端 | `http://localhost:5173` | 已启动，可访问 |

演示前请确认启动顺序：Broker → MySQL → 后端 → 模拟器/硬件 → 前端。

---

## 2. 演示脚本

### 开场（30 秒）

旁白：

> 大家好，今天演示 USN Lab Hub IoT 一个半月 MVP。我们通过 MQTT 接入实验室功耗监测设备 PM-001，实现从数据采集、告警、建议、指令下发到操作日志的完整闭环，并提供一个面向访客的公开项目展示页。

---

### 镜头 1：启动环境（40 秒）

操作：

1. 在终端依次启动 Broker、MySQL、后端、模拟器、前端。
2. 运行快速检查脚本：

```bash
mosquitto_sub -h localhost -p 1883 -t 'iot/power-monitor/PM-001/telemetry' -v
curl http://localhost:8080/api/iot/public/projects/power-monitor
curl http://localhost:5173
```

预期结果：

- MQTT 终端每 5 秒收到 telemetry 消息。
- 公开接口返回 `code=200` 和 PM-001 数据。
- 前端页面可访问。

旁白：

> 这是完整启动顺序：Broker、MySQL、后端、模拟器、前端。模拟器复用了与真实硬件完全一致的 MQTT Topic 和 JSON 协议。

---

### 镜头 2：未登录公开页（1.5 分钟）

操作：

1. 使用无痕窗口打开 `http://localhost:5173/iot/public`。
2. 等待页面自动加载数据。

预期结果：

- 页面展示 `power-monitor` 项目和 `PM-001` 设备。
- 显示电压、电流、功率和健康评分。
- 展示最近功率趋势折线图。
- 页面无登录入口、无控制按钮、无隐私信息。

旁白：

> 这是公开项目展示页。未登录访客可以看到项目编号、设备状态、最新指标、功率趋势和健康评分，但看不到任何管理入口、操作日志或 MQTT 凭证。

---

### 镜头 3：登录后总览页（1 分钟）

操作：

1. 在普通窗口打开 `http://localhost:5173/iot/overview`。
2. 使用管理员账号登录。

预期结果：

- 总览页展示项目数、在线设备数。
- PM-001 健康评分和未处理告警提示正常显示。
- 提供进入 PM-001 实时页和公开展示页的入口。

旁白：

> 登录后进入 IoT 总览页，这里展示项目摘要、设备在线情况和 PM-001 的健康评分，并提供管理入口。

---

### 镜头 4：PM-001 实时页（1.5 分钟）

操作：

1. 从总览页点击 `查看 PM-001 实时页`，进入 `/iot/pm001`。
2. 观察实时卡片、历史曲线、告警、建议、指令、日志六个区域。

预期结果：

- 实时卡片显示电压、电流、功率和上报时间。
- 历史曲线展示功率趋势。
- 告警、建议、指令、日志区域初始为空或有历史记录。

旁白：

> 这是 PM-001 的管理页面。上方是最新数据，中间是功率历史曲线，下方是告警、建议、指令和操作日志四个区域。

---

### 镜头 5：触发告警（1 分钟）

操作：

1. 修改模拟器输出，使 `power` 超过 100W，例如 110.5W。
2. 等待 5 - 10 秒。

测试数据：

```json
{
  "projectCode": "power-monitor",
  "deviceCode": "PM-001",
  "reportTime": "2026-07-15 14:35:00",
  "metrics": {
    "voltage": 220.1,
    "current": 0.50,
    "power": 110.5
  },
  "status": "online"
}
```

预期结果：

- PM-001 页告警区出现 `OPEN` 告警：功率超过 100W。
- 建议区出现 `PENDING` 建议：缩短采样间隔。
- 健康评分从 100 变为 70，`level` 变为 `ATTENTION`。

旁白：

> 现在模拟器上报功率 110.5W，超过 100W 阈值，系统自动生成 OPEN 告警和规则建议，健康评分降为 70。

---

### 镜头 6：确认建议并下发指令（1.5 分钟）

操作：

1. 在建议卡片上点击 `确认并下发指令`。
2. 观察指令区和操作日志区。

预期结果：

- 建议状态变为 `CONFIRMED`。
- 指令区新增 `SET_SAMPLE_INTERVAL` 记录，状态 `PENDING → SENT`。
- 操作日志新增 `SEND_COMMAND` 记录。
- 模拟器收到 MQTT command 消息。

旁白：

> 管理员确认建议后，系统下发 SET_SAMPLE_INTERVAL 指令，参数固定为 5 秒。指令状态先为 PENDING，发布到 MQTT 后变为 SENT。

---

### 镜头 7：收到 ACK 完成闭环（1 分钟）

操作：

1. 等待模拟器回复 ACK，约 1 - 3 秒。

预期结果：

- 指令状态变为 `ACKED`。
- 操作日志新增 `RECEIVE_ACK` 记录。
- 模拟器日志显示已调整采样间隔为 5 秒。

旁白：

> 模拟器收到指令并执行后，通过 ack Topic 返回 ACK。指令状态变为 ACKED，操作日志记录了 SEND_COMMAND 和 RECEIVE_ACK，业务闭环完成。

---

### 镜头 8：返回公开页验证边界（1 分钟）

操作：

1. 切换回无痕窗口的 `/iot/public`。
2. 等待 30 秒自动刷新，或手动刷新。

预期结果：

- 公开页功率显示 110.5W。
- 健康评分显示 70，`level` 为 `ATTENTION`。
- `reasons` 显示存在未处理的功率告警。
- 页面仍无控制按钮和操作日志。

旁白：

> 回到公开页，功率和健康评分已经变化，但公开页仍然只读，不会暴露任何控制能力。

---

### 收尾（30 秒）

旁白：

> 以上就是一个半月 MVP 的完整演示。我们实现了 MQTT 数据接入、MySQL 落库、告警、建议、指令、ACK、操作日志、健康评分和公开展示。第六周主要做测试、文档和答辩准备，第七周再考虑实时推送、多设备接入和规则引擎等方向。

---

## 3. 快速验收路径

如果时间紧张，可跳过镜头 1 和镜头 3，直接演示：

```text
公开页（30 秒） → PM-001 实时页（30 秒） → 触发告警（30 秒）
→ 确认建议并下发指令（1 分钟） → ACK 闭环（30 秒） → 返回公开页（30 秒）
```

总时长约 4 分钟。
